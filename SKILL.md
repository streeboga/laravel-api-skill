# Laravel API

## С чего начать (всегда)

1. **Правила проекта главнее этого скилла.** Прочитай CLAUDE.md или AGENTS.md репозитория. Расхождение решается в пользу проекта.
2. **Найди ближайший похожий сценарий в коде и скопируй его форму**: имена, каталоги, версии библиотек. Новый паттерн рядом со старым дороже любого плохого старого. Два стиля в коде — следуй ближайшему файлу; отступление только ради корректности или безопасности и названо в ответе. API пакета сверяй с `composer show <пакет>` и кодом в `vendor/`, не по памяти.
3. **Определи объём** по таблице «Какие файлы нужны». Лишние файлы — слоп, а не аккуратность.
4. **Задевает границу доверия** (маршрут, владелец или статус, деньги, токен, вебхук, исходящий HTTP, кэш/очередь/поиск, удаление) — до первого файла выпиши шесть строк: кто / что шлёт / контроль / граница / ресурс / тест. Метод — `references/secure-design.md`.
5. **Новая очередь, расписание, внешний вызов, денежная операция:** сразу реши, как увидишь её сбой и её молчание: `references/observability.md`.
6. Прочитай только нужный reference из таблицы внизу, не все.
7. **Баг:** сначала скажи, что значит «починено», потом узкий регрессионный тест. Крупная работа: короткий план с тестами до кода, мелкая правка без плана.
8. **Проверка красная — чини код.** Порог не занижай, тест не пропускай и не удаляй. Чего нет на входе — не выдумывай, назови пробел. Правило, которое нельзя терять, переноси в ArchitectureTest.

## Слои

```
Точка входа → Service → Repository → (QueryBuilder) → Model → DB
```

Точка входа — контроллер, команда, задание, слушатель, экран админки. Они равны: консольная команда не получает права обходить слои.

| Слой | Делает | Не делает |
|---|---|---|
| Точка входа | Принимает ввод, зовёт сервис, отдаёт результат | Запросы, репозиторий, бизнес-ветвления |
| FormRequest | Валидация с границами, `toDto()` | Правка смысла ввода (`strip_tags`) |
| Service | Правила, транзакции, очередь, кэш | `Model::query()`, HTTP-ресурсы, `$request`, `abort()`: отказ — доменное исключение |
| Repository | Все запросы и запись | Бизнес-решения |
| QueryBuilder | Сложный запрос с именем по смыслу; единственное место сырого SQL | CRUD, `$this`-состояние |
| Model | Связи, касты, аксессоры | скоупы в теле (общий скоуп — трейт из `app/Builders/Concerns`), бизнес-логика в наблюдателях |
| Resource | Белый список полей | Запросы, секреты |

## 12 правил, которые забываются первыми

Правило работает, когда его держит машина. Колонка «Держит» — что поставить в проекте; шаблоны в `templates/`.

| # | Правило | Держит |
|---|---|---|
| 1 | Точка входа зовёт только сервис | deptrac, `ArchitectureTest` |
| 2 | Запрос к модели только в репозитории | `ArchitectureTest` |
| 3 | Сырой SQL только в Builders: метод с именем, что он считает, значения биндингами. `DB::table` по таблице с моделью запрещён и в командах, и в сидерах | `ArchitectureTest` |
| 4 | Деньги — `Brick\Money` и один источник множителя; `float` и вторая константа запрещены | `references/money.md`, тест |
| 5 | Баланс, лимит, одноразовое действие — атомарно: `UPDATE ... WHERE` с проверкой числа строк, замок или резерв. Не «прочитал, проверил, записал» | тест на два параллельных запроса |
| 6 | Событие, задание, письмо, внешний кэш — только после коммита. HTTP внутри транзакции запрещён | ревью, `service-layer.md` |
| 7 | У задания `tries` или `retryUntil`, `backoff`, `timeout`, идемпотентный ключ; у `Http::` `timeout`, `connectTimeout` и `->throw()` или проверка статуса: 4xx/5xx исключения не бросают. Повтор запроса — только идемпотентного или с тем же `Idempotency-Key` | `ArchitectureTest` |
| 8 | Чужой ресурс: фильтр владельца в запросе и политика (404). `exists` с `where(владелец)`. Пустой список ограничений = пустой результат | тест с двумя арендаторами |
| 9 | Сбой проверки безопасности = отказ, а не пропуск: пустой секрет, пустое чтение настройки, недоступное хранилище отзыва | тест на отказ зависимости |
| 10 | `status`, `role`, владелец, цена, баланс не попадают в `$fillable`, достижимый из запроса | ревью, `$request->validated()` |
| 11 | У ввода границы: `max:` на строку и массив, потолок `per_page`, `throttle` на маршруте, `abilities:` на каждом маршруте токена (алиас заводится в `bootstrap/app.php`, Sanctum его не регистрирует) | тест маршрутов |
| 12 | PHPStan level 8 без baseline и `@phpstan-ignore`: подавление прячет причину | CI или прогон перед push |

Нарушение из таблицы — баг. Исключение пишется в проекте явным списком с причиной.

## Какие файлы нужны

Создавай только свою строку. Интерфейс, событие, DTO «на будущее» не создаются.

| Задача | Файлы |
|---|---|
| Новая запись CRUD | Миграция, модель, фабрика, enum статуса, FormRequest, DTO, репозиторий, сервис, контроллер, ресурс, политика, маршрут, тест |
| Только чтение | Запрос в репозитории, метод сервиса, контроллер, ресурс, маршрут, тест |
| Новое действие над сущностью | FormRequest (если есть ввод), метод `{Entity}{Action}Service`, контроллер, маршрут, тест |
| Команда или задание | Тонкая точка входа, метод сервиса, тест сервиса |
| Сложный отчёт | Метод QueryBuilder, метод репозитория, метод сервиса, тест на данных |

**Что добавлять только по причине:**

| Добавляй | Когда |
|---|---|
| Интерфейс репозитория или сервиса | Есть вторая реализация сегодня. Подмена в тесте — не причина: Mockery не мокает `final`, поэтому своё тестируй на тестовой БД, внешнее — `Http::fake` или рукописным двойником |
| Manager/Driver | Две реализации переключаются конфигом (`references/patterns.md`) |
| QueryBuilder | Сырой SQL или условие, повторённое в двух запросах. Обычный `where` живёт в репозитории: репозиторий, который только прокидывает вызовы в билдер, значит, что билдер лишний |
| Событие и слушатель | Несколько независимых реакций. Один прямой вызов читается и отлаживается проще |
| DTO | Больше трёх полей или различие «не прислали» и «прислали null» (`dto.md`). Не нужен: одно поле, фильтры списка, только авторизация, вебхук с подписью по сырому массиву |
| Пакет composer | Stdlib, Laravel и уже установленное не справляются, и лицензия проверена |

## Меньше слопа, понятнее агентам

- Удаляй заменённый код в той же правке. Совместимость, флаги и обёртки — только по названной причине.
- Имя говорит о деле: `WalletLedgerService::deposit`, не `Helper`, `Manager`, `Utils`, `process()`, `handleData()`.
- Сервис — одна зона ответственности. Перевалил за ~200 строк или группа методов просит свои зависимости — дели: `{Entity}{Action}Service`, `{Entity}QueryService`, `{Entity}RemovalService`, общая проверка в `{Entity}Invariants`. Предел не абсолютный: пара план/применение денег или один алгоритм остаётся целым. Циклы между сервисами запрещены.
- Запрос или запись в цикле запрещены: сначала пачка `whereIn`, `findMany`, `upsert`, потом цикл по карте.
- Метод короткий, вложенность не больше 4, ранний выход вместо `else`. Контроллер дробится так же: не больше 4 зависимостей. Больше 7 параметров — DTO.
- Перед новым методом поищи близнеца: копия с мелкой разницей расходится молча.
- Модель не шлёт уведомления и не ставит задания: это делает сервис.
- Поток виден из кода: без бизнес-логики в наблюдателях, магических `__call`, глобальных хелперов и конфигов для значения, которое не меняется.
- Комментарий объясняет **почему** (инцидент, ограничение, неочевидный выбор). Что делает строка — видно из строки. Докблок нужен только там, где тип шире PHP: `array<string, int>`, `Collection<int, Order>`, `@property`, `@mixin`.
- Не лови ошибку, чтобы её залогировать и бросить дальше. Лови узкий класс. Если ошибка не поднимается выше, след обязателен: комментарий, где она видна (метрика, `ok=false`, отказ вызывающего), или `Log::warning` с классом ошибки без ПДн. Клиенту не отдаётся `$e->getMessage()`.
- Не добавляй защиту от невозможного: `isset` у типизированного свойства, `null`-значения параметров ради гибкости.
- Инвариант назван рядом со своим тестом. Таблица «правило → тест» и карта каталогов в CLAUDE.md дают агенту то, что иначе он ищет дорогим чтением. Подробности домена — в отдельные скиллы проекта, не в CLAUDE.md, который всегда в контексте.
- В проекте есть граф кода — ищи через него, а не grep по всему дереву.

## Готово значит проверено

Запускай от узкого к широкому: сначала тесты затронутого каталога, полный прогон один раз перед push.

```bash
./vendor/bin/pint --dirty
./vendor/bin/phpstan analyse
./vendor/bin/deptrac analyse --no-progress
./vendor/bin/sloppy   # если установлен
php artisan test tests/Feature/<Затронутое>
php artisan test --parallel
```

- Команды идут через `&&`: `;` и конвейер `| tail` прячут упавший код возврата, и push уходит поверх красных тестов.
- `sloppy agents install` ставит проверку на правки агента. Правило sloppy выключается только с причиной в конфиге.
- Одна тестовая база — один прогон. Два параллельных прогона на общей базе дают ложные падения.
- Новый инвариант — тест, который падает при его нарушении. Сначала увидь его красным.
- Тест на изменённое поведение и его важные сбои, не сверх. Правки текста без теста. Чужие тесты без согласия не удаляются. Разовые проверочные скрипты не заводятся, если поведение доказано тестом.
- Покрытие 85 % — ориентир проекта, а не цель теста. Для денег и прав важнее мутационный балл (`references/quality.md`).
- В тестах с HTTP — `Http::preventStrayRequests()`. Состояние (`env`, `config`, лимитеры), изменённое тестом, возвращается.
- Правка влияет на интерфейс или выкладку — проверь в браузере или на бою, тесты этого не докажут.

## JSON:API

Формат `{data: {type, id, attributes, relationships, links}}` через `TiMacDonald\JsonApi\JsonApiResource`. `PATCH` на обновление, `201` + `Location` на создание, `204` на удаление, ошибки `{errors: [...]}`, `?filter[x]=`, `?sort=-created_at`, `?page[number]=&page[size]=`, `?include=`. Фильтры и сортировка — белым списком `spatie/laravel-query-builder`; неизвестное поле даёт 400, а не молчаливое игнорирование. Тело запроса плоское: это сознательное отступление от спецификации. Подробно — `references/api-resources.md`.

## Ловушки, стоящие цикла PHPStan

- `now()` даёт `Illuminate\Support\Carbon`. Для `CarbonImmutable` пиши `now()->toImmutable()`.
- `->map()->values()->all()` PHPStan не считает `list`. Присвой результат и оберни в `array_values()`.
- `SoftDeletes` молча прячет закрытого владельца от `find()` и `belongsTo()`. Код денег, истории и админки берёт `withTrashed()`, код входа и действий — нет.
- `Model::fresh()` возвращает nullable: используй `refresh()`.
- `$request->user()` nullable: первой строкой `abort_if($user === null, 401)`.
- `PHP_INI_SCAN_DIR` от herd-lite грузит grpc дважды в homebrew-PHP: дочерний процесс после `pcntl_fork` молча умирает, параллельные прогоны теряют воркеры.
