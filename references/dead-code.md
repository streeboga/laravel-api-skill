# Мёртвый код

Код без вызывающего — не запас, а долг: его читают, тестируют, правят при рефакторинге, а работает он только в воображении. Хуже всего код, живущий ради своего теста: зелёный тест доказывает защиту, которой в рабочем пути нет.

## До того как писать

Новый класс или метод появляется только вместе с тремя вещами в той же правке:

1. **Вход:** маршрут, команда, задание, слушатель, хук фреймворка или вызов из уже живого кода.
2. **Вызов:** строка, которая его зовёт, написана сейчас, а не «потом подключим».
3. **Тест через этот вход:** тест идёт снаружи, как ходит настоящий путь.

Нельзя выписать вход — метод не нужен. Не пиши `findBy…`, `isX()`, `hasY()`, `values()`, `label()`, `toArray()`, геттеры и состояния фабрик «на всякий случай»: заводи, когда появится первый вызов. Контракт и драйвер без второй реализации — то же самое.

## Что считается мёртвым

| Признак | Что делать |
|---|---|
| Нет ни вызова, ни теста | Удалить в этой правке |
| Вызывается только из тестов | Либо подключить в рабочий путь, либо удалить вместе с тестом. Эталон для сверки с другим языком — в `tests/Support`, не в `app` |
| Защита или проверка без вызывающего | Сначала выяснить, нужна ли она: это либо дыра, либо мусор. Не удалять молча и не подключать вслепую |
| Копия живого кода | Оставить одну, вторую заменить вызовом |
| Заменили путь (снесли старый механизм) | Снести всё, что им питалось: методы репозитория, билдеры, DTO, enum, драйверы, конфиг, пакет |
| Доступен только другой части мёртвого кода | Мёртв весь остров. Поиск по имени его не видит, нужен граф достижимости |

Перед удалением ищи и строки (`'name'`, `[X::class, 'm']`), но помни: **одноимённый метод другого класса — не вызов.** Поиск по имени занижает мёртвое, инструмент достижимости завышает его, если не знает входов. Правда — на пересечении, спорное проверяется глазами.

## Проверка

PHPStan level 8 с нулём ошибок ничего не говорит о мёртвом коде: публичное он не проверяет. Нужен shipmonk.

1. `composer require --dev shipmonk/dead-code-detector edalzell/dead-code-detector-laravel`.
2. Положи `templates/phpstan-dead.neon` в корень, `templates/FrameworkUsageProvider.php` в `phpstan/`, в `autoload-dev` добавь `"PHPStanHub\\\\": "phpstan/"`: провайдер нужен на компиляции, `bootstrapFiles` не годится. Веток провайдера под пакеты, которых нет в проекте (Filament, Pennant), быть не должно: убери их, отсутствующий класс роняет анализ.
3. Запуск: `vendor/bin/phpstan analyse -c phpstan-dead.neon`. Ноль находок — часть проверок перед коммитом.

Тесты исключены (`usageExcluders.tests`), поэтому метод, который зовут только тесты, показывается мёртвым. Этого и добивались.

Ложная находка значит, что анализ не видит вызов фреймворка. Чини правилом в провайдере с записью, кто именно зовёт: контейнер, очередь, Pennant, жизненный цикл Filament, канал уведомления, шаблон письма, ресурс через `__get`. `@phpstan-ignore` и `ignoreErrors` здесь не ставятся.

Спорное сверяй рантаймом: полный прогон с xhprof даёт рёбра «кто зовёт кого», на PHP 8.4 с именами замыканий `{closure:/path/file:line}`, так что вызов из `tests/` отличим от боевого. Вызовы только из тестов или ни от кого — мёртвое. Вызовы из `Illuminate\\*` — вход, который анализ не видит: закрой провайдером. Граф кода годится как третье мнение, но на PHP он связывает вызовы по имени.

Каждую находку разбери до одного из исходов: подключить, удалить, закрыть провайдером с указанием вызывающего. Обёртку, которую зовут только тесты, удаляй и переводи тест на живой метод. Эталон сверки цен и денег переноси в `tests/Support`. «Шум» — не исход.
